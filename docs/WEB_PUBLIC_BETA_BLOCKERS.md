# AI-LifeOS Web Public Beta 上线阻断清单

更新日期：2026-10-28
状态：**未达到公网 Public Beta 上线条件**

本清单只覆盖公网 Web Beta 的发布门禁。004-X 智能追问已经功能冻结；Ollama、
LM Studio、多模型自动池、手表导入和食物照片识别不进入本次上线范围。

## 1. 004-X 冻结结论

- 真实 DeepSeek 已验证：多记录自动保存、首轮 AI 联合评估、回答更新原记录、
  刷新持久化、单次发送与单次上游调用控制。
- 第二轮真实请求成功返回零个有效问题。零问题属于合法业务结果。
- 页面曾因零问题直接隐藏整个追问组件；现已最小修复。正常零问题显示“本轮
  没有新的有效补充问题，智能补充已完成。”，请求失败显示独立失败提示。
  同一标签页刷新后恢复结束状态与历史；第三轮后不会生成第四轮。
- 不再要求第三轮真实推理。现有日志不能区分模型原始空数组与候选全部被过滤；
  另一个独立 correlationId 的调用来源也无法确认。两者保留为冻结边界。

## 2. P0：Public Beta 前必须解决

### P0-1. 用户自带 API Key 的安全链路

当前正式生活记录解析使用服务端环境变量中的个人 Key，尚无面向公测用户的
BYOK 安全实现。上线前必须确定并验证：

- Key 仅通过 HTTPS 从浏览器发送到受控服务端，不进入 URL、日志、错误监控、
  `localStorage`、`sessionStorage` 或长期 Cookie。
- 默认只在当前请求或明确的短时服务端会话中持有；刷新后的行为必须清楚说明。
- 服务端使用固定 Provider Base URL 白名单，禁止用户自定义 URL，防止 SSRF。
- Key、生活原文和完整模型响应不写入普通遥测。
- 用户可随时断开、覆盖和清除连接信息。
- 浏览器不直接调用第三方模型服务，避免 CORS 暴露 Key 和绕过服务端限流。

### P0-2. 三步模型连接

公网页面目前没有完整的公开模型连接设置。Beta 上线至少需要完成：

1. 选择 Provider。
2. 输入该 Provider 的 Key。
3. 获取或选择模型、测试连接并设为当前模型。

当前首页仍说明“本机测试版暂不提供公开账号和模型设置”。连接状态、错误状态、
真实 AI / 规则降级标签和断开入口必须同屏可用。模型 ID 可提供手动输入兜底，
但不能开放自定义 Base URL。

### P0-3. 多实例严格幂等

当前 `IdempotencyStore` 是单进程内存 `Map`。它已通过单实例并发、完成重放、
冲突拒绝和 Follow-up 分轮测试，但不同实例之间不共享状态。

公网 Beta 若允许多个 Serverless / Node 实例，必须在调用模型前使用共享原子存储
完成 action ID 的占位、冲突校验和结果复用。否则同一动作可能跨实例重复推理和
计费。临时只允许单实例部署时，也必须把该限制写成明确发布约束和监控门禁。

### P0-4. 数据隔离与隐私边界

Public Beta 的默认数据模型仍是“记录保存在当前浏览器”，不得把设备本地数据描述
成已云同步。上线前必须验证：

- 一个用户的服务端请求不能读取另一个用户的浏览器记录。
- 附件继续保存在浏览器 IndexedDB；服务端不持久化用户记录或图片。
- 清除浏览器数据会删除本地记录，页面提供清楚的备份导出/恢复入口。
- 发送给第三方 AI 的文字、图片、Provider、模型和可能的保留政策有明确告知。
- 正式隐私政策和用户条款替代当前“不是正式隐私政策”的测试说明。

### P0-5. 公网路由、CSRF 与滥用保护

当前 `proxy.ts` 的公网测试模式只开放 `/model-test` 及其 API，主应用并未完成
公网白名单迁移。上线前必须：

- 明确允许公开的页面和 API，默认拒绝 OAuth 管理、LAN 登录、Health、Telegram、
  系统文件和任何本机管理端点。
- 对写操作校验同源 Origin、Host、CSRF 和请求体大小。
- 限制输入长度、输出预算、并发、速率、超时和 Provider 费用风险。
- 禁止未带 Key 的公共付费调用和开发者个人套餐共享。
- 确认安全响应头和 CSP 不会破坏真实页面、PWA 与回调。

### P0-6. 生产构建、HTTPS 与部署配置

当前本机生产构建仍受 `.next` `EPERM` 环境问题阻断，不能据此判断应用代码失败。
Beta 前必须在独立干净环境完成生产构建并记录结果，然后：

- 使用真实 HTTPS 域名和有效的服务端环境变量。
- 验证 `/`、聊天、Follow-up、图片上传、备份恢复和 PWA 静态资源。
- 验证 HTTP 到 HTTPS、Cookie 属性、Origin 和反向代理头。
- 确认公网地址不是个人电脑端口映射，也不暴露本机 OAuth 凭据。

### P0-7. 手机优先与真机验收

已有 390×844 视口和部分触控验证，但公网 Beta 仍需要真机关键路径验收：

- Android Chrome：输入、自动保存、编辑、删除、日历、统计、备份、模型连接。
- iPhone Safari：同一关键路径、键盘遮挡、安全区、文件选择和 PWA 添加。
- 公开 HTTPS 环境下的 PWA manifest、图标、启动路径和独立窗口显示。
- 清理浏览器数据风险、换设备不自动同步、网络失败不误报保存成功。

无法真机测试的平台必须标记未验收，不能用桌面模拟视口代替。

### P0-8. 开源合规与法律文本

AGPL-3.0 对应源代码入口目前仍未建立。上线前至少需要：

- 与运行版本一致的公开 Corresponding Source 地址，并从页面显著可达。
- 上游版权、LICENSE、Life OS MIT 通知和第三方依赖通知完整。
- 当前锁文件对应的 SBOM 或等价清单。
- 对 `TERMS_OF_USE.md` 的解释冲突取得确认。
- AI 独立服务边界仅作为工程事实记录；是否构成法律独立作品仍需专业确认。

## 3. P1：Public Beta 上线后

- Ollama、LM Studio 和本地模型自动发现。
- TokenHub 及其他 Provider 的多模型池、自动切换、额度策略和质量评分。
- 更多 Provider 的实时目录、计费提示和真实 API 验收。
- 第三轮及后续真实 AI 动态追问。
- 手表运动、心率和睡眠文件导入。
- 饮食照片识别与可选营养分析。
- 跨设备云同步、账号体系、Firebase 与本地存储统一。
- 完整离线 AI、推送通知、复杂 PWA 缓存策略。
- 微信小程序与 Web 的功能对齐和共享服务扩展。

## 4. 发布判定

只有全部 P0 关闭、生产构建通过、HTTPS 公网地址可用、真机关键路径通过，且
隐私文本与对应源码入口可访问后，才能称为 Web Public Beta。P1 中任何功能都不
得阻塞本次上线。
