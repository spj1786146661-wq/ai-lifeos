# 网页版 AI 智能延伸对话 v1

更新日期：2026-10-28（Asia/Shanghai）

## 目标

用户发送一条生活描述后，现有流程继续解析并自动保存合法记录。首轮真实 AI 在同一解析请求中联合评估本次全部已保存记录，最多返回三个按价值排序的补充问题；第二、第三轮只在用户主动继续时各发起一次新的评估。用户回答后只更新对应的原记录，不创建重复副本。

本轮只修改网页版。微信小程序、Health、Telegram、Proxy、AGPL 声明、存储迁移、Firebase 和 OAuth 均未修改。

## 实现

- `lib/life-parse-server.ts` 的首轮提示词要求模型检查本次全部记录，允许零到三个跨记录问题，并明确禁止重复询问已知字段。一次用户消息仍只发起一次首轮解析请求。
- 成功的 AI 解析可以明确返回零个问题；代码不会再用机械规则问题替代模型“无需补充”的判断。
- `normalizeFollowUpQuestions()` 校验 `recordIndex`、记录类型、目标字段、轮次、优先级、长度和重复问题，并按优先级排序、最多保留三个。
- `filterKnownFollowUps()` 删除答案已存在于记录中的问题；`mapFollowUpsToSavedRecords()` 把解析器索引映射到实际写入后的记录 ID，未保存或重复跳过的候选不会得到可操作问题。
- `lib/life-follow-up-server.ts` 生成第二、第三轮问题。每次显式调用最多发起一次上游请求，不自动重试，也不会为每条记录分别调用模型。TokenHub、ChatGPT 套餐和 OpenRouter 复用现有 Provider。
- `normalizeSavedRecordFollowUpQuestions()` 只接受本次相关记录范围内的目标 ID，过滤已知字段、已回答字段、已跳过字段、重复文本和已使用的问题 ID，最多保留三个。
- `components/life-records/SmartFollowUps.tsx` 支持一张卡片对应一个问题和一个目标记录，逐题回答、逐题跳过、全部跳过、结束补充，以及用户主动继续第二或第三轮。
- `applyFollowUpAnswer()` 只接受该记录类型允许的补充字段；保存前在现有权威存储锁内重新读取原记录。字段冲突会拒绝静默覆盖，记录 ID 和记录数量保持不变。
- 每次补充在 `LifeRecord.supplements` 中保留问题、回答、字段、来源、轮次和创建时间；原始 `sourceText`、来源引用和附件关系继续保留。

## 会话和轮次

- 首轮问题映射到本次真实保存的记录 ID。
- 回答一个问题不会清空其他问题，也不会自动触发下一轮。
- 只有当前轮所有问题均已回答或跳过，用户主动点击继续时，才会请求下一轮。
- 第三轮结束后不再生成第四轮。
- 当前轮次、问题、已回答/已跳过状态和历史保存在浏览器 `sessionStorage`，刷新后可恢复；记录中的补充字段保存在原权威存储中。
- 会话快照同时保存本次自动保存产生的全部记录 ID。后续轮次会联合检查这些记录，即使第一轮某条记录没有获得问题，也不会在第二轮被遗漏。
- 旧版会话快照没有完整记录 ID 列表时，只从历史问题和待答问题恢复已知 ID，保持向后兼容。
- `sessionStorage` 只保存追问元数据和记录 ID，不保存 API Key、OAuth Token 或服务端日志。

## 安全与异常

- 动态续轮接口只接受本机回环请求，并检查 Host、Origin、Referer 与 `Sec-Fetch-Site`；局域网客户端不能调用电脑上的个人 AI 凭据。
- 请求体限制为最多 12 条相关记录，并对记录 ID、日期、字段和请求大小做服务端校验。
- AI 返回空内容、非 JSON、字段不合法或超时时，原记录仍已保存；续轮会明确显示规则降级。不会把规则问题标记为真实 AI。
- 同一问题重复回答、迟到轮次、跨记录错误写入和已有值冲突均有拒绝逻辑。
- 不新增真实 TokenHub 推理请求；本轮验证全部使用 Mock 和合成记录。

## 尚未进行

- 本轮没有新增真实 TokenHub 或 ChatGPT 模型调用，因此“真实模型能否稳定生成三个跨记录问题”和“第二、第三轮真实动态质量”仍需单独授权后人工验收。
- 当前轮次面板在刷新后通过 `sessionStorage` 恢复；关闭浏览器会话后，面板状态不保证保留，但已经写入原记录的补充字段仍会保留。
- 用户尚未提交的输入框草稿不会跨刷新保留。

## 人工验收建议

1. 发送同时包含睡眠、运动、饮食的合成消息，确认记录自动保存且首轮最多出现三个问题。
2. 检查问题分别显示关联分类、记录摘要、轮次、优先级和真实 AI/规则来源。
3. 回答运动问题，确认只有运动记录更新，睡眠和饮食不变，记录总数不增加。
4. 跳过另一个问题，确认剩余问题仍可回答。
5. 解决当前轮后主动点击继续，观察第二、第三轮是否基于更新后的全部记录生成新问题。
6. 刷新页面，确认当前轮次、已回答和已跳过状态恢复。
